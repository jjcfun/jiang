# Stage0 TODO

这份文档用于整理 stage0 阶段仍待完善、尚未定型，或虽然已部分支持但仍带明显限制的语言功能。

原则：

- stage0 尽量补齐语言表面语法与核心语义
- 对未来一定会重做的大块能力，若暂不实现，应明确从 `jiang.md` 中降级为 future，而不是继续写成“像是已支持”
- 优先收敛会影响语言整体模型和编译器内部实现的能力

## 高优先级

### 1. Async

`jiang.md` 已有 `Async` 章节，但当前前端与实现仍未真正支持：

- lexer 未提供 `async` 关键字
- parser / hir / jir / llvm 后端没有完整 async 语义链路
- 文档当前更像语法占位

需要决定：

- 在 stage0 完整实现 `async`
- 或从 `jiang.md` 中移除/降级成 future 设计

### 2. Package 机制补全

该项不再属于 stage0 范围。

当前 package 机制维持最小版：

- 只识别 `package.ini` 中 `[package]` 的 `name` / `root`
- 依赖只支持本地路径
- 只支持 `import dep;`
- 还不支持 `dep/submodule`

后续留到 stage1 再讨论与扩展。

### 3. Extend 能力收敛

当前 `extend` 仍有这些限制：

- 只支持扩展当前文件里已经声明过的本地 `struct` / `enum` / `union`
- 不支持 `init`
- 不支持 `deinit`

需要决定：

- 是否继续保持这些限制直到 stage1
- 或在 stage0 就把跨文件 / 跨模块扩展模型收清楚

### 4. Trait 同名 requirement 冲突

当前规则是：

- 若一个类型同时声明多个 trait，而这些 trait 中存在同名 requirement，则直接报错

这条规则目前简单可行，但会限制 trait 组合能力。

后续方向：

- 保持当前规则直到 stage1
- 或在 stage0 引入显式消歧机制

## 中优先级

### 5. Trait 关联类型继续完善

当前还未支持：

- 关联类型默认类型

此外还可继续收敛：

- 父子 trait 关联类型绑定与推断规则
- 更完整的 `@where(...)` 与关联类型交互

### 6. Defer 控制流限制

该项已定型，不再作为 stage0 待办。

`defer` 体内永久保持不支持：

- `return`
- `break`
- `continue`
- `?? return`
- `?? break`
- `?? continue`

### 7. Range 能力扩展

当前 `Range` 只支持：

- 左闭右开区间 `start..end`

需要决定是否在 stage0 增加：

- 其他区间形式
- 更完整的 range 迭代语义
- 更多 range 相关方法

### 8. For 循环能力

该项已定型，不再作为 stage0 待办。

当前保持：

- 不支持隐式索引迭代
- 如需索引，需要显式 `.indexed()`

### 9. 名义类型内部函数模型

当前文档仍写明：

- 第一版使用 `static` 区分类型函数与实例函数

如果 stage0 目标是定型完整语法，需要判断：

- 这是否就是最终风格
- 还是还要继续调整

## 指针 / 内存模型

### 10. 指针与释放语义继续定型

当前仍是默认堆分配器模型：

- `T*` 可通过 `ptr$.free()` 主动释放
- `T&` 不参与释放
- many-pointer 不提供更多指针算术语法

文档里也明确说明：

- 所有权
- 借用
- 多 allocator

这些仍是 future。

stage0 需要决定：

- 继续维持当前最小模型
- 或在 stage0 就引入 allocator / 更清楚的释放语义

### 11. many-pointer 能力

当前 `T[*]`：

- 支持下标
- 不支持 `offset()` 等额外语法

需要决定是否在 stage0 扩展。

## 类型与字面量

### 12. 字符串/字节模型

当前字符串字面量仍按 UTF-8 字节序列处理：

- `UInt8[_]`
- `UInt8[]`

需要决定是否在 stage0 保持这个模型不变，还是引入更明确的字符串/字节分层。

### 13. 数值自动提升范围

当前自动提升仅覆盖：

- `Int`
- `Float`
- `Double`

若 stage0 目标是补完类型行为，需要决定是否扩大自动提升规则。

## 结构体构造与初始化

### 14. 默认字段初始化模型

当前：

- `Type { ... }` 已彻底禁用
- 统一使用 `Type(...)`
- 若类型没有 `init`，默认字段初始化只支持 `field: value` 标签形式

需要决定：

- 是否继续保持这个模型
- 是否需要扩展无标签初始化或其他字段初始化规则

## 文档一致性

### 15. 清理“已写文档但未落地”的条目

需要系统检查 `jiang.md` 中以下几类内容：

- 已写语法但尚未真正实现
- 当前只是第一版占位
- 已改变实现但文档还保留旧表述

重点章节：

- `Async`
- `Package`
- `Trait`
- 指针/内存相关章节

## 建议推进顺序

1. 先决定 `Async` 是实现还是降级为 future
2. 收敛 `extend` / trait 同名 requirement 这几块核心结构
3. 再处理指针 / allocator / range 等仍可继续演化的能力
4. 最后统一回收文档不一致与残余第一版表述
