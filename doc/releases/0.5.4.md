# Jiang 0.5.4

Jiang 0.5.4 adds definition-level reflection and file generation. Ordinary Jiang code can inspect
modules, declarations, types, documentation and typed metadata, then generate files through a dedicated entry.

## Highlights

- `@entry(main)`, `@entry(lang)` and `@entry(generate)` select root declarations by role and validate
  their contracts. Lang and generate entries may be private and do not require fixed names.
- `reflect` exposes read-only handles and structured signatures, module import edges, exports,
  generic definitions and source locations. It does not expose function bodies or compiler IR.
- `@meta(expr)` attaches compile-time values to declarations; `@meta(module: expr)` targets a module.
  Typed queries share the same metadata for Jiang source and custom Lang output.
- `jiang generate .` calls the package root's generator once. Named configurations select a dependency
  package or an internal module; the input remains the using package's root.
- Generation provides resource snapshots, staged output publication and explicit local cache reads and
  writes. Stable fingerprints reuse the compiler's semantic facts and dependency tracking.
- Lang packages can parse whole source files through extension mappings, including a package root.
  `[dependencies]` registers packages; Lang and generate aliases reference those dependencies.
- Import expressions produce namespaces for `alias` bindings and compile-time selection. Ordinary
  compile-time evaluation shares the JIL executor, with storage reuse and invalid-reference checks.

- Scheduled destruction now rejects a Task owner that still carries an unfinished capture borrow,
  before marking the owner moved. Awaited owners and ownership transfer retain their existing behavior.

## Migration

Select the provider type with `@entry(lang)` instead of relying on the public name `Lang`. It must
implement `std.jiang.syntax.Provider` and be constructible without arguments.

Prefer `alias name = import "file.jiang";` for named imports and `public alias name = import ...;`
for re-exports. Use an alias initialized by a conditional expression for conditional imports;
local bindings inside a comptime block do not become module declarations.

Generation uses `@entry(generate)` and the `generate` command. There are no comptime kinds or
`comptime [generate]` blocks. A named generation configuration specifies exactly one of `package`
(a dependency alias) and `module` (an internal relative file path); there is no `--generator` option
or per-task input-root override. Package manifests remain `package.ini` in this release.

## Building

The strict bootstrap chain starts with Jiang 0.5.3 stable, builds the fixed `bootstrap/0.5.4`
stage, then builds release next and release stable. See [the development guide](../develop.md).

Usage and API boundaries are documented in [the language guide](../jiang.md#生成与模块反射) and
[reflection architecture](../compiler/reflection.md). A documentation website generator and
`#package` configuration are outside this release.
