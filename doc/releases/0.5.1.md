# Jiang 0.5.1

Jiang 0.5.1 adds Linux x86_64 as a hosted release platform and improves repeated and parallel builds.
Its self-hosting chain starts from Jiang 0.5.0 stable through a pinned 0.5.1 transition compiler.

## Highlights

- Prebuilt compiler packages for macOS arm64 and Linux x86_64.
- Linux hosted executable linking through the native libc and toolchain; the packaged compiler requires
  glibc 2.34 or newer and does not dynamically depend on LLVM or lld.
- Persistent source/object artifacts with safe invalidation and reuse across builds.
- Parallel debug-package object emission, using the process's available CPU count by default and an
  optional `--jobs N` limit.
- Reusable compiler sessions, in-memory source overlays, structured diagnostics, and definition/type/span
  queries as foundations for later tooling.
- Generic initializer inference and partial generic arguments such as `Foo<_>`.

## Language and library changes

- Closure capture lists accept existing locals through `[name]`, `[ref name]`, and `[ref! name]`.
- Shared references to `Sendable` values can cross Domains while remaining subject to lifetime checking.
- `coroutine.sync(domain) { ... }` replaces the old `sync [domain] { ... }` block syntax.
- Atomic ordering operations use overloads without the `_with_order` suffix, and Boolean CAS is named
  `compare_and_set`.
- `system.cpu.available_count()` reports the logical CPU count available to the current process.

## Scope

This release does not include Linux no-libc, Linux arm64 packages, or an LSP. LSP work is deferred to a
later release; the compiler-service foundation remains available for that work.
