# Jiang 0.5.2

Jiang 0.5.2 strengthens ownership and lifetime checking, adds consuming callables, and substantially
reduces the compiler's cold self-host time and peak memory use. Its reproducible source bootstrap starts
from Jiang 0.5.1 stable and passes through two pinned transition compilers.

## Highlights

- The compiler source now self-hosts under strict ownership checking. Mutable receivers, aggregate
  projections, reborrows, and cross-call provenance are checked consistently instead of relying on the
  transition compiler's audit mode.
- Reference lifetime shapes preserve the outer borrow separately from the referenced value's structural
  lifetime shape. Generic nominal types and callable signatures retain these relationships across package
  interfaces and monomorphization.
- `FnOnce` supports closures that consume owned captures. Async `FnOnce` transfers its environment into the
  coroutine frame and is used by `Task` and `coroutine.sync` where the callback runs once.
- Query-driven declaration observations and object artifacts provide narrower invalidation and reusable
  compilation results.
- Generic JIL bodies are retained through borrow checking; reachable concrete instances, layout, drop glue,
  coroutine variants, and backend code are produced on demand.
- Borrow-check and backend data structures were reduced and their hot paths were reorganized. On the
  compiler development benchmark, cold self-host time fell from 289.4 seconds to about 116 seconds and peak
  RSS fell from 4.74 GB to about 2.3 GB.

## Language and library changes

- `Void` is the spelling of the void type; `()` is its single value. A `Void` function may use `return;`.
- `T*!` is the writable raw-pointer type, while `T*` remains read-only. Optional writable raw pointers such
  as `T*!?` are supported.
- Mutable capability violations that older compilers missed are now diagnosed. Code that writes through a
  shared receiver must use an actual mutable reference or writable raw pointer.
- `Fn` remains repeatable and cannot move a non-Copyable owned capture from its borrowed environment.
  `FnOnce` expresses the consuming form explicitly and cannot be called through a borrowed callable.
- Lifetime contracts support structural generic and callable paths without introducing a second provenance
  model.

## Toolchains and packages

- Hosted packages are produced for macOS arm64 and Linux x86_64.
- Release compilers statically link the managed Jiang LLVM 22 toolchain; users do not need an LLVM runtime.
- The source release can be reproduced with the pinned chain
  `0.5.1 -> bootstrap/0.5.2 -> bootstrap/0.5.2-2 -> release/0.5.2 next -> release/0.5.2 stable`.

Linux no-libc, Linux arm64 release packages, and an LSP remain outside this release.
