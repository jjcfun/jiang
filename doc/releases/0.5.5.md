# Jiang 0.5.5

Status: preparing for release. Published downloads remain on 0.5.4 until release validation completes.

Jiang 0.5.5 moves package configuration into ordinary Jiang source and expands the public syntax API
for custom languages. It also unifies named arguments and provides shared language contexts.

## Highlights

- `package.jiang` replaces `package.ini`. Builtin `#package` expands to an ordinary public `info`
  constant of type `std.jiang.PackageInfo`; normal type checking and compile-time evaluation apply.
- Importing the package file exposes `package.info`, including `package.info.version`. Package loading
  and ordinary imports share module identity and evaluated constants. Dependencies and root files
  are loaded after package information is available.
- Named arguments and named keyword options use `=`. Type constraints and lifetime relations retain `:`.
- A Provider can initialize a shared `LangContext` with `create_context(Session&)`; `Session.intern`
  produces keyword IDs compatible with default tokens. Stateless providers can use the defaults.
- Public parsers expand nested RawBlocks and classify results through `AstRole`, including individual
  members and declaration/member sequences. Custom tokenizers can register and expand nested blocks.
- Context-owned `List<T>` handles simplify AST construction. Parser checkpoints restore cursor,
  diagnostics, AST changes and managed lists, including attributes attached to existing nodes.
- Single- and double-quoted tokens are named by their lexical form. Their Jiang AST meanings remain
  character and string literals. Character AST construction rejects empty text, multiple Unicode scalars
  and invalid UTF-8; single-quoted tokens remain available for other languages to interpret.

## Migration from 0.5.4

### Package configuration

Replace `package.ini` with `package.jiang`. Use field assignments, semicolons and named child blocks:

```jiang
#package {
    name = "app";
    version = "0.5.5";
    type = .bin;
    root = "src/main.jiang";
    dependencies {
        tools = "../tools";
    }
    lang schema {
        package = tools;
        extensions = ["schema"];
    }
}
```

From `src/main.jiang`, `import "../package.jiang";` makes `package.info.version` available.
The exported name is `info`; it follows ordinary name-conflict rules. Cross-package imports must use
declared dependencies. Configuration cannot depend on the root, providers or generators it is preparing.

`#doc` and other Attribute results are accepted between package fields and at the end of child blocks.
They are ignored there; fields are not declaration nodes. Document the package declaration from outside
the `#package` block when the documentation should attach to `info`.

### Named arguments and options

Change `foo(version: "1.0.1")` to `foo(version = "1.0.1")`, including method and constructor calls.
Change named keyword options similarly, for example `async [domain = ui_domain]` and `struct [align = 8]`.
Do not replace colons globally: type annotations, trait constraints and lifetime mappings still use them.

### Custom language providers

Keep `@entry(lang)` on the Provider type. Update scan/parse contexts to `SyntaxContext<LangContext>&`.
Pass `context.syntax` to parser/tokenizer construction and read shared language data through `context.lang`.
Implement `create_context(Session&)` when supplying a custom `LangContext`; omit both for the default
`EmptyLangContext`. Shared state belongs to one compilation session; block Provider instances remain separate.

Use `Attribute` terminology in place of the previous `Annotation` API names. Expand nested blocks with
`parse_raw_block()`, inspect their role, and explicitly attach attributes with `with_attributes`.
No automatic attachment is inferred from node creation order or across nested scopes.

Checkpoints restore only parser-managed state. Provider fields, ordinary vectors and external effects
are not rolled back. Use managed lists for pending attributes that must participate in rewind.
Do not reuse AST/list/checkpoint handles across contexts or after their creation has been undone.

Rename `TokenKind.char_lit` to `single_quoted` and `TokenKind.string_lit` to `double_quoted`.
Their `SymbolId` payload contains decoded text; token spans retain the original source range.
AST literal categories and builder `char_literal`/`string_literal` names remain unchanged.
Rebuild custom language providers against the updated public API.
