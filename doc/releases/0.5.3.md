# Jiang 0.5.3

Jiang 0.5.3 unifies ordinary algebraic data types under `enum`. Enum cases can carry no payload, one
payload, or several named payload fields, while retaining integer representations and explicit case
values. The separate error-union representation used by `Result` remains unchanged.

## Highlights

- Payload cases use `case`, `case(T)`, and `case(T left, U right)` syntax. Cases come before methods
  and nested types, with `;` separating the two sections.
- Generic payload enums support construction, pattern matching, exhaustive `switch`, recursive-value
  diagnostics, ownership, active-case destruction, custom `deinit`, and cross-package interfaces.
- Payload enums retain `enum [IntType]` representations, implicit case numbering, explicit integer
  values and enum-to-integer conversion. No-payload integer enums retain `Type.init?(integer)`.
- Ordinary `union` declarations and their compiler identities have been removed. Payload enums use the
  existing tagged-sum layout, JIL, borrow, and drop paths rather than a parallel implementation.
- Ordinary `Domain` values now provide runtime execution identities with deterministic Executor ownership.
  Canonical `const` Domain bindings retain their static fast path, while runtime Tasks keep accepted work alive
  without extending the Domain value's borrow lifetime.
- The first stable `std` surface includes UTF-8 strings, owned paths, Vector/HashMap/HashSet, portable file errors,
  owned file reads, eager directory traversal, process utilities, clocks, entropy, synchronization, and diagnostics.
- Lang providers now use `SyntaxContext`, generic `Tokenizer<K>` / `Parser<K>`, typed syntax handles, and an
  opaque `Ast` root; compiler AST storage and the former public Builder/Tree representation are no longer exposed.

## Lifetime changes

- A scalar source in a field or payload `@life` binding fills the complete lifetime shape of that
  top-level position. Positional, named, and explicitly expanded forms remain equivalent.
- Reference shapes keep the outer borrow separate from the complete pointee shape. A grouped source is
  required only when nested positions need different lifetimes; partial or flattened bindings are rejected.
- `Fn` and `Fn^` carry one closure-environment lifetime position. An owned `Fn^` owns its closure object
  and by-value captures, but borrowed captures remain constrained by their original sources.
- `T^` owns its allocation and pointee value. If the pointee contains non-owning references, the owner
  retains those lifetime requirements rather than extending their sources.

## Bootstrap and validation

The reproducible cold-start chain is:

```text
Jiang 0.5.2 stable
  -> bootstrap/0.5.3 next
  -> release/0.5.3 next
  -> release/0.5.3 stable
```

The bootstrap worktree produces only `jiangc.next`; release next is compiled directly with that binary,
and release stable is then compiled with release next.

The final release compiler passed all 1,380 language cases. On the cold self-host benchmark it completed
in 116.32 seconds with a 29.222-second backend phase and 2,373,568 KiB peak RSS. Relative to the 0.5.2
baseline, total time increased by 0.06%, backend time increased by 1.57%, and peak RSS increased by 0.61%.

Linux no-libc, Linux arm64 release packages, and an LSP remain outside this release.
