# 反射与生成

反射提供定义级编译期内省，生成器用普通 Jiang 代码查询、转换并输出文件。
它们复用编译器的语义事实、编译期执行和缓存机制，让 Jiang 源码与自定义语言使用同一套生成能力。
使用生成器不要求创建 Lang package。

本文说明设计目标和整体架构。用法见[语言指南](../jiang.md#生成与模块反射)，
完整 API 见 [reflect](../../src/compiler/core/reflect.jiang) 和
[generate](../../src/compiler/core/generate.jiang)。

## 能力边界

- `reflect` 提供声明、类型、模块关系、文档和 metadata 的只读信息，不开放函数体或编译器内部 IR。
- `generate` 负责生成入口、资源读取和输出发布；生成文件不在同一轮重新作为输入参与编译。
- Lang Provider 负责把自定义语法转换为定义和附着信息，结果接受普通语义检查。
- 普通 comptime 可以查询已知类型及相关定义；生成器另有输入范围查询和文件输出能力。

`#doc` 负责文档语法与附着，反射提供 Markdown 和组织文档所需的模块、声明与来源信息。
页面、导航、锚点和依赖图如何呈现由生成器决定。

## 入口与执行

`@entry(kind)` 显式声明入口角色，编译器检查相应类型契约，不依赖固定函数名。
每个 root、每种角色至多一个显式入口；`lang` 和 `generate` 入口可以保持私有。
生成入口是非泛型、同步的 `Void (reflect.Module)` 函数。

package 可以配置多个命名生成任务，每次选择其中一个；命令行可选择输入和生成器。
生成器与输入分别有自己的 root，可以来自不同 package。普通 build/check 不自动运行生成任务。

```text
选择输入和生成器
  → 加载源码与生效的导入关系
  → 完成语义检查，准备定义级事实及生成器执行依赖
  → 调用一次生成入口，传入输入 root
  → 成功后发布输出
```

全量语义检查与按需 JIL 准备各司其职：前者发现未被调用的声明错误，后者只准备执行所需代码。
进入生成阶段后，输入定义集合保持稳定；查询可以惰性派生结果，但不扩展输入源码或临时触发其单态化。
用户泛型以定义形式提供，已知具体类型的成员则按实参解释。

一次入口内的遍历和输出顺序由 Jiang 代码决定。生成阶段采用顺序执行模型，
不隐式遍历执行依赖包的任务，也不自动并发调用生成器。

## 公共模型与范围

公共类型统一位于 `reflect`。声明以带类别 payload 的 `Decl` 表示，通过模式匹配取得
`Function`、`Struct`、`Enum` 等句柄；共同属性属于声明，类别属性属于相应类型。
签名、类型结构、约束和 lifetime 契约以结构化信息提供。

查询返回轻量句柄与可重复遍历的只读视图，不复制一套编译器模型。
句柄支持语义身份比较，仅在当前编译期会话中有效；可物化的普通值可以作为输出或缓存内容。
筛选、排序和收集使用普通 Jiang 代码。

范围遵循显式的拥有关系与模块图：

- 模块集合包含输入 root 所在包内实际导入可达的模块，平铺去重；不扫描未导入文件。
- 导入查询保留直接边、绑定和跨包目标。导入图允许环，不等同于目录树。
- 声明和成员按源码顺序枚举，不进入函数体，也不沿类型引用无限展开。
- 公开导出描述对外绑定，保留重导出名称和重载，不能简单等同于 public 声明筛选。

生成器自身导入的模块不自动成为输入范围。输入包内可查询私有定义，跨包查询遵循公开边界；
必要的私有类型引用保持不透明身份。反射权限不改变普通代码的可见性。

泛型定义、具体类型及原始声明保留各自身份，具体成员查询带有实参环境。
extension 独立表示，不合并到目标类型的直接成员中。lifetime 契约参与约束检查，
不参与类型身份或重载区分；类型身份与契约内容变化须分别表达。

## 文档与 metadata

`#doc` 为模块或声明附着文档。没有文档仍是有效定义，生成器可以结合导入边、声明归属、
导出名和原始位置组织文档。自定义语言保留原始输入的来源身份。

`@meta(expr)` 使用普通 Jiang 类型承载声明标签，`@meta(module: expr)` 附着到模块。
表达式按普通编译期规则求值，结果必须可物化；查询按精确语义类型匹配，重复附着保留顺序。
内建 attribute 的专用语义属性与用户 metadata 分开查询。

Lang Provider 与普通源码产生同一种 metadata 附着，统一由使用方编译器求值和检查。
Provider 只构造语法，不另行解释标签。跨文件、跨包的求值错误应保留触发位置及调用链。

## 共同语义事实与依赖

反射、普通编译期求值和编译过程共享语义 query、缓存结果、事实指纹及失效规则。
已有事实保持原有所有权，metadata 由查询系统管理；反射不建立另一份语义模型或指纹算法。

依赖粒度由共同 query 决定，而非反射 getter 的数量。例如返回整个签名的查询，
其消费者依赖签名事实，不自动跟踪随后对返回结构体的字段访问。
集合依赖涵盖顺序、范围及空结果；文档、metadata 和来源与不读取它们的签名事实分离。

普通 comptime 的按需查询由编译编排层准备依赖，求值器保持执行职责；
generate 在准备完成后执行，不负责驱动输入的语义检查。
持久化使用稳定身份与内容指纹，不保存会话句柄或宿主地址。

不提供函数体反射，不等于忽略函数体依赖：参与常量或 metadata 求值的函数实现变化，
仍须使消费其结果的检查或生成失效。所有消费者共用该依赖关系。

## 输出与缓存

资源读取取得本轮稳定快照，输出先暂存、成功后统一发布，失败不发布不完整结果。
输出目录由任务专用，生成器不得覆盖输入源码；执行及资源使用受编译期预算约束。

生成器入口始终调用一次，由其显式使用缓存跳过局部转换。编译器负责生成器实现、
配置及缓存版本的依赖，生成器负责声明局部任务使用的输入指纹。
声明、模块和资源指纹具有明确范围；引用类型内容、递归模块及额外资源按输出需要显式组合。

缓存可以保存中间数据或最终内容，命中后仍由生成器选择如何发布输出。
语义缓存和生成产物缓存共享输入管理与指纹基础设施，但分别表达语义事实和生成结果。
更多共同机制见 [Database](database.md) 与[增量编译](incremental.md)。
